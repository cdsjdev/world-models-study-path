World Models

What it means for a model to hold an internal state of the world, predict how that state changes, and reason about actions it never actually took.

The core idea: state, not just pixels

A video representation (the previous topic) answers how do we encode what we see. A predictive world model asks: given the current state and, where applicable, an action, what could happen next? That state may be an explicit latent variable, a sequence of tokens, or another learned representation. There is no single universally accepted architectural definition of a world model; prediction and action-conditioned simulation are the central ideas used in this tutorial.

This idea predates deep learning by decades: it comes from control theory and robotics, where a state-space model tracks position, velocity, and other latent variables well before any neural network is involved. What's new in the last several years is learning that state representation directly from raw video, at scale, instead of hand-engineering it.

The three jobs of a world model

Almost every world model, from small robotics research systems to Cosmos-scale foundation models, is organized around three functions:

1. Encode: build the state
Encode raw observations such as video frames and sensor readings into a learned state representation. This may reuse the tokenization and attention mechanisms from the previous topic, but the representation must preserve information useful for the downstream prediction objective; reconstruction alone does not guarantee that.
2. Predict: roll the state forward
Given the current state (and optionally a proposed action), predict the next state. This is the transition function. Repeating it produces a rollout: a sequence of imagined future states, which can be decoded back into video if needed.
3. Evaluate / plan: use the predictions
Score predicted futures against some objective (safety, task success, plausibility) and use that score to choose actions, flag anomalies, or simply report a hypothesis to a human reviewer.

In Cosmos 3, these functions are exposed as two modes of a unified omnimodal architecture. Reasoner mode maps text and visual inputs to text for understanding, grounding, physical reasoning, planning, and action forecasting. Generator mode denoises multimodal tokens to produce images, video, synchronized sound, or actions, depending on the checkpoint and task. Neither mode by itself guarantees calibrated uncertainty or physically correct predictions; those properties must be evaluated.

Prediction under uncertainty

The future is not deterministic from a single video clip. If a pedestrian is standing at a crosswalk, they might step out, wait, or turn around: the clip alone doesn't tell you which. A world model that predicts only one future (a single most-likely rollout) will systematically miss possibilities, especially rare but important ones like a wrong-way vehicle or a sudden stop.

Two broad strategies handle this:

  • Stochastic / multimodal prediction: the model outputs a distribution over possible next states (or samples several plausible rollouts) instead of a single point prediction. This is expensive but honest: it surfaces the cases where the model itself is unsure.
  • Calibrated confidence: the model still produces a single best guess, but attaches a probability or confidence score that is trained to actually match its real accuracy (a 70% confidence prediction should be right about 70% of the time). This is cheaper but only useful if the calibration is trustworthy.

This is where world models connect directly to the evaluation topic later in this phase: a model's uncertainty output is only useful if it's calibrated, and calibration is something you measure, not something you assume.

Counterfactual simulation

A counterfactual asks: what would have happened if X were different? In world modeling, this means running the transition function forward from an observed state but under a hypothetical action or condition that didn't actually occur: for example, simulating what a scene would look like at night, or how traffic would flow if a lane were closed, starting from a real daytime clip.

Counterfactual simulation is the theoretical basis for Cosmos Generator's synthetic-data role: generating night, rain, fog, or camera-angle variants of a real clip is a counterfactual query: same underlying scene, different condition: and it is only useful to the extent the world model's transition function accurately captures how that condition actually changes the visible world, not just how it changes surface-level pixel statistics.

A caution worth internalizing

A conditionally generated video can look realistic and still be wrong about the causal structure of the world: for example, rain may change surface appearance without correctly changing visibility, traction, or behavior. Visual plausibility is not physical correctness, and merely changing a prompt does not establish a valid causal counterfactual. This is why the study plan requires synthetic data to prove its value on held-out real footage before it is trusted.

Planning: turning predictions into decisions

Planning is the step where predicted rollouts get compared and a course of action gets chosen: the classic setting is model-based reinforcement learning, where an agent imagines several action sequences, predicts each one's outcome using the world model, scores the outcomes, and picks the best-scoring action. This is powerful because it lets an agent "think ahead" without acting in the real world first. But it inherits every weakness of the prediction step: if the world model is wrong, the plan built on top of it is wrong too, often in ways that are hard to detect until execution.

For camera-driven, operator-assist systems specifically, full autonomous planning is deliberately out of scope: the goal is prediction and explanation feeding a human decision, not an agent acting on the world model's imagined rollouts. Understanding planning conceptually still matters, because it clarifies exactly what capability is being withheld and why: the system boundary that keeps a human in the loop is a planning boundary, not a prediction boundary.

Glossary

TermMeaning
StateA compressed representation believed to capture everything relevant for prediction.
Transition functionThe learned function that maps (state, action) → next state.
RolloutA sequence of predicted future states produced by repeated transitions.
CalibrationHow well a model's stated confidence matches its actual accuracy.
CounterfactualA simulated "what if" scenario that did not actually occur.

Study checklist

Before moving on, you should be able to
  • Distinguish a world model's job from a video representation's job in one sentence.
  • Name the three functions (encode, predict, evaluate) and give an example of each.
  • Explain why a single deterministic prediction is dangerous for rare events.
  • Explain why visual plausibility is not the same as physical correctness in a counterfactual.
